## Goal

`/revoice --build` decides KEEP or DROP for each extracted sample **on the user's machine**, with plain rules and no network call. No email leaves the machine for the review step: not to Claude's model provider, not to the text analysis API. The API still receives only the kept samples (at most 100) for the voice profile in phase 5, as today.

## Why

The review rules are simple text checks, and the text analysis API runs in production in lite mode with no models, so it had nothing a local script lacks. Sending up to 200 emails to the API for review would expose more of a user's mail than today, cost credits, and add a dependency. revoice is open source, so the rules are public anyway.

## Current State (main)

- `skill/revoice/build/review-samples.py` (epic 2 T1, PR #14) posts every sample in `samples/index.csv` to `POST /analyze/sample-review` on the API, which does not exist (the route returns 401/404), then writes `verdict,score,reason` columns.
- `skill/revoice/build.md` phase 4 runs it, and on failure offers an opt-in fallback where Claude reads every sample. Every build therefore hits an error first today.
- The rules to keep are the fallback's own text: DROP a sample when it is mostly text the author did not write (pasted articles, quoted email that slipped through, boilerplate, forwards); lists, logs, code, tables or schedules rather than prose; form letters sent many times; written in someone else's name or voice; not in the author's usual language. `score` 1-5: 5 = several paragraphs of the author thinking and explaining in their own words; 1 = barely any real writing.
